# Expo iPad navigation (SDK 57)

Adds four features to an existing Expo SDK 57 app. Each is optional, but steps 3 and 4 build on
step 2's tab view, and step 5 needs step 4.

| Feature | How |
| --- | --- |
| Floating top tab bar that expands into a sidebar with extra sections | Local module `modules/sidebar-tabs` (SwiftUI `TabView` `.sidebarAdaptable` + `TabSection`) |
| Search as a separate search tab | `role="search"` on a `SidebarTab` (SwiftUI `Tab(role: .search)`) |
| Search field across the top (iPad) / at the bottom (iPhone) | `searchPrompt` on `SidebarTabView` (`.searchable` on the search tab) |
| Open a page in a new window (button + drag-out) | Local module `modules/page-windows`, its config plugin, and a custom `index.tsx` entry |

Why custom native code at all: SDK 57 has no `TabSection`, no search-role tab with
`.searchable`, no API to open a window, and its scene delegate can't pass per-window initial
props. See [references/decision-guide.md](references/decision-guide.md).

Templates live in `templates/`, laid out as they go in the target app. `src/example-data.ts`,
`src/screens/*` and `src/components/page-detail.tsx` are placeholders: replace them with the
app's own data and screens. The native module names (`sidebar-tabs`, `page-windows`) can stay.

## Prerequisites (check first, stop if unmet)

- `expo` `~57.0.27` (at least `57.0.23` for scene support), `react-native` `0.86.x`,
  `@expo/ui` `~57.0.22`, `expo-router` `~57.0.25`. Run `npx expo install --fix` after adding deps.
- Continuous Native Generation (`ios/` generated by prebuild). With a committed `ios/`, apply the
  same Info.plist and AppDelegate changes by hand.
- macOS with Xcode 26+, an iPad simulator (and an iPhone one for the compact layout).
- Runtime: iOS 18+ for the sidebar and sections; iOS 17 falls back to a plain tab bar.

## Steps

Work in order. Each step ends with a check; do not start the next step until it passes.

1. **Xcode 26 build fix.** Copy `templates/scripts/patch-expo-modules-jsi.js` and
   `templates/patches/`, add `"postinstall": "node scripts/patch-expo-modules-jsi.js"`, run
   `npm install`. Check: `npx expo run:ios` builds. Details: [references/xcode26-patch.md](references/xcode26-patch.md).
2. **Sidebar tab view.** Copy `templates/modules/sidebar-tabs`. Make the main window's route
   render `SidebarTabView` inside one `@expo/ui` `Host` (see `templates/src/app/index.tsx`), with
   main tabs first and sidebar-only tabs given a `section`. Remove the split views' own sidebar
   buttons with `removeSidebarToggle()`. Check on iPad: bar at the top, sidebar button shows
   the sections; on iPhone: bottom bar, sections under More.
   Details: [references/sidebar-tabs.md](references/sidebar-tabs.md).
3. **Search tab.** Add a `SidebarTab` with `role="search"` (list it first, as Apple News does).
   Check: iPad shows Search as a separate button beside the bar.
4. **Search field.** Pass `searchPrompt` and `onSearchTextChange` to `SidebarTabView`; use
   `requestedSearchText` + `searchRequest` to fill the field (recent searches). Build the
   search page from `templates/src/screens/search-screen.tsx`. Check: iPad field is full width
   at the top and stays put while typing; iPhone's tab bar turns into the field.
5. **Page windows.** Copy `templates/modules/page-windows` and `templates/index.tsx` (adapt its
   `PageWindow` import), set `"main": "./index.tsx"`, add `expo-build-properties`, and register
   the plugins in this order:
   `"./modules/page-windows/app.plugin.js"` then
   `["expo-build-properties", { "ios": { "enableSceneSupport": true } }]`.
   Add `pageDragOut(...)` to list rows and an Open in New Window button (iPad only). Check:
   `npx expo prebuild -p ios --clean` succeeds and the button opens a second window.
   Details: [references/multi-window.md](references/multi-window.md).
6. **Verify everything** with [references/verification.md](references/verification.md),
   including `npx tsc --noEmit` and `npx expo-doctor` in the target app.

Read [references/pitfalls.md](references/pitfalls.md) before step 5; most failures there are
silent (a blank window, a stuck splash screen, a dropped scene delegate).

## Rules

- Keep iPad-only controls (Full Screen, Open in New Window) behind `Platform.isPad` /
  `canOpenPageWindows`; iPhone has one window and one column.
- A page window renders a non-router root. Never mount a second Expo Router `App` in it.
- Never write a partial `UIApplicationSceneManifest`; the plugin writes the whole dictionary.
- Drag-out cannot be automated in the simulator. Say so in the report; do not claim it passed.
- Report custom native size honestly: about 330 lines of Swift plus a 38-line plugin
  ([references/decision-guide.md](references/decision-guide.md#size)).

To remove a feature later, follow [references/removal.md](references/removal.md).
